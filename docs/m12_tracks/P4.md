# Milestone 12 – pod P4: library growth (as built)

Design: `docs/milestone12.md` §6.4 (D24, growth order), §14.3 (user OK of 11 Oct 2026: "1a, 2 all four; go on with
P4"); track B as built: `docs/m12_tracks/B.md`. Cloud session, CPU only, 11 Oct 2026. No pod was started; no library
model was downloaded here (metadata only: `git ls-remote`, the Hugging Face API, raw files of gz-fuel-tools). The
Infinigen part was tried here on the CPU (code and Python packages, no model files): the pinned clone, `uv sync

## 1. What the pod does

One job, `scripts/jobs/library_growth.sh`, takes the four approved lists (`results/library/growth/approved_*.json`,
read through `growth.approved`, the ingest gate) to audited catalogue entries:

| Source | Approved | Licence | What the pod does |
|---|---|---|---|
| Poly Haven | 88 models | CC0 | `fetch_model` at **1k** glTF into `/workspace/assets/models/<id>/` (§4.1) |
| ABO | 232 GLBs (7.8 GB) | CC BY 4.0 | download into `/workspace/assets/models/abo/abo_<id>.glb`; the 30 headboards are downloaded but not catalogued (no catalogue type `headboard`) |
| Google Scanned Objects | 36 archives (0.24 GB) | CC BY 4.0, **confirmed per object** | unpack safely, licence evidence per object, OBJ -> GLB in Blender 5.2 into `models/gso/<uid>.glb` |
| Infinigen | 30 jobs (12 factories) | BSD-3-Clause code, models ours | pinned v1.19.0, own venv, generate, bake, OBJ -> GLB into `models/generated/<id>.glb`; time cap |

Then for the new models: catalogue entries in the existing formats, written **only into copies** under the audit
root (`/workspace/library-audit/p4/audit/catalogue/`), and the audit of the new models with the audit package (P2's
render with the scale reference, the code checks, P3's vision question, `decide.py` with user decision 1a, contact
sheets, the writer). The 4 models P3 left pending get their second vision pass in the same server session. Gaps are
computed over the whole library.

## 2. Command (the lead runs it; nothing was run here)

    python3 scripts/gpu_run.py run --job scripts/jobs/library_growth.sh --gpu 'RTX PRO 6000' --disk 150 \
      --max-minutes 110 --env AUDIT_MODEL_KEY=agent --purpose "M12 P4: library growth"

Needs on the volume: P2/P3's audit folder (`/workspace/library-audit/audit/`: `measure.json`, `code.json`, the
answers; without it the P3 pending models are skipped and the rest runs), the assets folder and Blender 5.2.2 (from
`scripts/pod_setup.sh`). Env (optional): `AUDIT_ROOT`, `GROWTH_ROOT` (`/workspace/library-growth`), `WENART_ASSETS`,
`AUDIT_WORKERS` (3), `INFINIGEN_CAP_MIN` (40), `INFINIGEN_TEX_RES` (1024), `GROWTH_PH_SIZE` (1k).

## 3. Steps and minutes

Background steps start first (explicit pids; `join_bg` waits for one pid, never a bare `wait`):

| Step | What | Minutes |
|---|---|---|
| setup-check (bg) | vLLM + the model of `AUDIT_MODEL_KEY` (`pod_setup_polish.sh`, part check), as P3 | 8–12 |
| infinigen (bg) | uv 0.12.18 + Python 3.11 + the pinned commit and its two submodules + `uv sync --frozen --no-install-project` (bpy 4.2.0, scikit-image built from source; a second try without scikit-image) 5–10, factory list and import check, 30 jobs (seed 0 of every factory first), CPU bake at 1024 px 5–20 | ≤ 40 (cap) |
| ingest-polyhaven (bg) | 88 × `fetch_model` (1k), retries | 1–3 |
| ingest-abo (bg) | 232 GLBs, 8 parallel downloads, retries, size limit = listed size + 25 % | 2–6 |
| ingest-gso (bg) | 36 archives from the HF mirror at the listed revision | < 1 |
| gso-licence | safe unpack (no `..`, no links, 600 MB cap), evidence per object, keep / drop | 1 |
| convert-gso | `convert_blender.py`: OBJ (Z up, metres) -> GLB | 1–2 |
| catalogue | every new model measured with numpy (`glbmesh.py`), entries, copies validated | 2–4 |
| render-a | `audit render --ids-file new_ids.json` (P2's render, 3 Blender workers, ≈ 4 s per model) | 8–14 |
| join infinigen | waits for the capped Infinigen part | – |
| convert-infinigen, catalogue-b, render-b | the Infinigen models (axes checked against Infinigen's own size) | 1–3 |
| code | `audit code --ids-file`: the new models, duplicates checked against the whole library | 1 |
| ask | one vLLM session: P4 pass 1 + pass 2, P3 pass 2 of its pending models (answers reused) | 4–8 |
| decide, write, vision-fields, pending, sheets, gaps, preview, report | `audit decide/write/sheets` on the copies, `growth run ...` | 2–4 |
| gpu-tests | `pytest -m gpu tests/gpu/test_library.py -k growth` | 1–2 |

**Expected 50–65 min; worst case ≈ 85 min** (Infinigen cap 40 + ≈ 30 after it + slow downloads), inside the pod's
95-minute `WENART_DEADLINE` (110 − 15). The Infinigen cap is `min(job start + 40 min, deadline − 30 min)`; a step that
would not fit before the deadline is skipped and recorded (exit 1). **A second run of the same command finishes a cut
run**: downloads keep complete files (`.part` then rename), unpacked archives and conversions are reused by sha256,
measurements by the file hashes, renders by `job_sha`, answers by their input hash, Infinigen jobs by their
`result.json` (no setup when none is left), and no vLLM server starts when every answer is current (the setup still
running in the background is stopped).

## 4. Decisions

### 4.1 Poly Haven at 1k, not 2k
The approved list was measured at 2k (501 MB). `wenart/furniture/fit.py: fetch_models` asks `fetch_model(...,
size="1k")` for every Poly Haven model: a 2k entry would make every run download the 1k files again (or fall back to
the parametric mesh offline), and P2 rendered the 34 old models at 1k. So the pod fetches 1k (`GROWTH_PH_SIZE`), the
same files the fit and the Blender build already resolve (`gltf: models/<id>/<id>_1k.gltf`, `resolution: 1k`), less
than the approved size. 2k needs a fit change (track S: fetch at the entry's `resolution`).

### 4.2 Entries (`wenart/assets/audit/growth_entries.py`)
- Formats: Poly Haven as in `catalog.json` (furniture in `entries` with `styles` + `style_note`, decor in `decor` as
  `decor_<type>` without `kind`, `url`, `api_url`, `gltf`, `resolution`, `dimensions_api_mm`, `sha256_gltf`); ABO, GSO,
  Infinigen as in `catalog_library.json` (frame fields, `licence_flag`, credit fields, `unit_scale` 1.0 with
  `unit_note`, `units_known`, `glb` = `models/<source>/<uid>.glb` (= `models.library_relpath`), `sha256_glb`, counts,
  `textured`, `vertex_colours`).
- Boxes: `glbmesh.measure` reads the glTF / GLB with numpy (scene graph, node transforms, Y-up -> Z-up as Blender's
  importer); checked here against Blender 5.2's own import of a rotated, scaled hierarchy (same box, same vertex count).
  The audit render measures again in Blender and its pivot check compares (1 cm).
- Front: ABO's documented -Y (`high`); else the geometric rule of the type (`objaverse.yaml` front rules: `medium`,
  note `geometry: ... front <axis>`); else -Y `low` with the reason, so the vision answer names it (`decide.py`
  turns a front only where code is unsure).
- Styles: the source's hint (ABO listing style / family, Poly Haven title and tags) or `neutral`; after the vision
  question the hint plus at most 3 styles of the answer (`apply_vision_fields`). Beds: `has_mattress` false until
  the vision answer sees bedding.
- Every new entry starts with `audit = {status: pending}`: nothing uses it before the P4 decision is written.
- Infinigen models are `source: generated` (licence `generated (Infinigen v1.19.0, BSD-3-Clause)`, the `generated`
  record names the factory, the seed and the commit, `generator: infinigen`, credit line with Princeton's copyright):
  the fit, the build and `ATTRIBUTION.md` handle them like the other generated models. `write.generated_credit` (B2)
  no longer overwrites their credit; `GENERATED_NOTICE` names Infinigen too.
- The 3 Infinigen models without a type of ours (dishwasher, microwave, kitchen cabinet) are not catalogued: their
  audit sheets are in `audit/p4/preview/`.
- `catalog.json` copy: a type that gets Poly Haven models loses its parametric entry there (validate: a type is
  library or parametric; `catalog_library.json` already has models of every such type, so the merged catalogue does
  not change). The list is in `catalogue.json` (`parametric_replaced`) and in the copy's notes.

### 4.3 GSO licence (`wenart/assets/audit/growth_gso.py`)
Two sources per object, both recorded in `licence_evidence` and `results/library/growth/gso_licences.{json,md}`:
the archive's own text files (a licence file, `model.config`, `metadata.pbtxt`, a readme) and the object's Gazebo
Fuel record (`GET https://fuel.gazebosim.org/1.0/GoogleResearch/models/<name>`; endpoint and fields `name`, `owner`,
`license_name`, `license_url` read in gz-fuel-tools `FuelClient::ModelDetails` / `JSONParser::ParseModel`). Kept:
one source states CC BY 4.0 (the licence URL, "CC BY 4.0", "Creative Commons Attribution 4.0", or a Fuel licence
naming Attribution and 4.0) and none names another licence; dropped otherwise, with the reason. GSO is a new library
source `gso` (CC BY 4.0, credit "by Google Research, Google Scanned Objects (CC BY 4.0), <Fuel page>; changes: ...",
notice `objaverse.GSO_NOTICE`); OBJ imported Z up, Y forward (Gazebo's frame), metres; the archive's texture is the
base colour when the .mtl does not reach it; ids longer than 64 characters get a hash (`gso_uid`).

### 4.4 Infinigen (`growth_infinigen.py`, `infinigen_driver.py`)
- Pinned: tag `v1.19.0` = commit `01c39c7f7adcf7363ccbcc57c64410c69f4a4e7c` (`git ls-remote`, 11 Oct 2026). `main`
  is Infinigen 2 (`infinigen2`, `procfunc`), whose indoor factories moved; v1.19.0 is the last v1 release. Its
  `pyproject.toml`: Python `==3.11.*`, `bpy==4.2.0`, BSD-3-Clause; `uv.lock` resolves 44 packages (checked with
  `uv sync --frozen --dry-run`); docs/Installation.md: "Minimal install ... ok for Infinigen-Indoors or single-object
  generation".
- Factories matched at that commit (official list `tests/assets/list_indoor_meshes.txt` plus every
  `class ...Factory(` under `infinigen/assets/objects`, 274): toilet `ToiletFactory`, bathtub `BathtubFactory`,
  bathroom sink `BathroomSinkFactory`, kitchen sink `SinkFactory` (basin + tap, no cabinet), oven `OvenFactory`,
  beverage fridge `BeverageFridgeFactory`, dishwasher `DishwasherFactory`, microwave `MicrowaveFactory`, kitchen
  cabinet `KitchenCabinetFactory`, books `BookStackFactory`, bowl `BowlFactory`, pot `PlantContainerFactory` (a pot
  with a plant for `plant_small`; `PotFactory` is a cooking pot). The pod lists them again and records the list.
- Generation: Infinigen's own `generate_individual_assets.build_and_save_asset` with `--render none --save_blend -G
  --export obj` (its documented exporter bakes the procedural materials into textures), one child process per job
  with a 10-minute limit, CPU bake (`configure_cycles_devices` not called: bpy 4.2's kernels predate the GPU); the
  size of the exported meshes goes into `result.json`, and our converter picks the OBJ axes that give that size.
- **Two submodules are needed** although the docs' minimal install does not fetch them (found by the trial here):
  `infinigen/infinigen_gpl` @`10c1d76f5c35003e919be7265185c9c355e3b70c` (**GPL-3.0**: `infinigen/assets/materials/
  __init__.py` imports its snow surface, so no factory imports without it) and `infinigen/OcMesher`
  @`bb895a01b8f574da10be1df470210df7463a75c7` (BSD-3-Clause; `infinigen/terrain/core.py`, reached through
  `core.placement.camera`). Both are fetched on the pod at the commits the tag pins (`git ls-tree`) and only run
  there, like Blender (GPL) itself; nothing of them is copied into the repo or the catalogue, and the toilets, sinks
  and appliances are made by the BSD-3 factories. **Flag for the user** (CLAUDE.md: flag licences).
- Trial here (Python 3.11.17, bpy 4.2.0, 4 CPUs): all 12 factories import and generate (seed 0, 256 px: 5–23 s, the
  plant pot 75 s with 2 M triangles; 1024 px: toilet 11 s, oven 22 s), the OBJs convert with Infinigen's own size
  (off 0 % for 10, 25–33 % for the plant pot and the kitchen cabinet: some of their objects are not exported), and the
  entries validate. What the audit will see: the toilet (0.48 x 0.79 x 1.03 m), bathtub, bathroom sink, bowl, books
  pass the code checks; the kitchen sink (`SinkFactory`, a basin with a tap, 0.76 x 0.62 x 0.51 m) "lies on its side"
  for our `sink_kitchen` (a counter unit), the oven (1.42 x 1.04 x 1.64 m) and the beverage fridge (1.34 x 1.04 x
  1.18 m) at their default sizes are far off the size table (removed: known units). A follow-up could pass real
  dimensions to the appliance factories; the batch is a test.

## 9. Open risks

| Risk | Effect | Mitigation |
|---|---|---|
| The Fuel records do not state CC BY 4.0, or the API is not reachable from the pod | GSO objects dropped (the user's condition) | listed with the reason in `gso_licences.md`; nothing else waits on them |
| Infinigen setup (Python 3.11 download, scikit-image build, bpy 4.2 on the pod) or a factory fails | fewer or no Infinigen models | tried here end to end; recorded (setup.json, check.json, result.json); cap 40 min; the rest goes on; a second run retries what failed once |
| The GPL-3.0 submodule `infinigen_gpl` (needed to import Infinigen) | a licence question for the user | runs on the pod only, nothing copied, the models come from the BSD-3 factories; flagged here |
| Infinigen appliances at their default sizes | oven and beverage fridge removed by the size check | a test batch; a later step can pass real dimensions |
| Infinigen's CPU bake is slower than 1.5 min per asset | fewer than 30 models | seed 0 of every factory first |
| An ABO GLB larger than its listed size + 25 % | that model is not downloaded | recorded; one approved model is 251 MB (limit 314 MB) |
| Space on the volume | ≈ 11 GB new: ABO 7.8, Poly Haven 0.2, GSO archives + unpacked ≈ 0.8, Infinigen blends, OBJs and GLBs ≈ 1–2 (the plant pots have ≈ 2 M triangles), audit views ≈ 0.5 | the lead checks the free space before the pod (`scripts/jobs/volume_report.sh`) |
